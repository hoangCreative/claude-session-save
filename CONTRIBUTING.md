## Tiếng Việt

### Cách đóng góp (ngắn gọn)

1. Fork repo về tài khoản của bạn.
2. Tạo nhánh mới từ `main`: `git checkout -b sua-loi-abc`.
3. Sửa, rồi chạy thử (xem `TESTS.md` để biết cách chạy bộ test).
4. Commit theo quy ước bên dưới.
5. Mở Pull Request, mô tả rõ bạn đổi gì và vì sao.

Không có thay đổi nào quá nhỏ. Nếu bạn ngại, cứ mở một issue hỏi trước, mình trả lời.

### Bắt đầu từ đâu nếu bạn mới

Tìm các issue gắn nhãn **`good first issue`**. Đó là những việc mình cố ý để dành cho người lần đầu góp: phạm vi gọn, không cần hiểu hết codebase, có gợi ý sẵn trong issue. Nhãn **`help wanted`** là việc mình thật sự cần tay giúp, hơi rộng hơn một chút.

Nếu chưa biết chọn gì, mở issue mới với nhãn `question`. Hỏi là chuyện bình thường.

### Quy ước commit

Dùng dạng ngắn, có tiền tố cho biết loại thay đổi:

```
<loại>: <mô tả ngắn, viết thường, không chấm cuối câu>
```

Các loại hay dùng:

- `feat:` thêm tính năng mới
- `fix:` sửa lỗi
- `docs:` đổi tài liệu (README, file này, v.v.)
- `test:` thêm hoặc sửa test
- `refactor:` dọn code, không đổi hành vi
- `chore:` việc lặt vặt (cấu hình, dọn dẹp)

Ví dụ: `fix: doc dung ten file khi co dau cach`. Viết tiếng Anh hay tiếng Việt đều được, miễn người sau đọc hiểu.

### Một lưu ý riêng cho văn tiếng Việt trong repo

Mọi văn tiếng Việt trong repo này (commit, issue, tài liệu, comment) **tuyệt đối không dùng dấu gạch dài em-dash** (ký tự U+2014, trông như thế này nhưng dài hơn dấu nối). Thay nó bằng dấu phẩy, dấu hai chấm, hoặc tách thành câu riêng.

Lý do: đây là quy ước giọng văn của dự án, giữ cho câu tiếng Việt đọc tự nhiên như người nói. Văn tiếng Anh không bị ràng buộc này.

## English

### How to contribute (short version)

1. Fork the repo to your account.
2. Create a branch off `main`: `git checkout -b fix-something`.
3. Make your change, then run the tests (see `TESTS.md` for how).
4. Commit using the convention below.
5. Open a Pull Request describing what you changed and why.

No change is too small. If you feel unsure, open an issue and ask first. I will answer.

### Where to start if you are new

Look for issues labeled **`good first issue`**. These are deliberately scoped for first-time contributors: small, no need to understand the whole codebase, with hints already in the issue. The **`help wanted`** label marks things I genuinely need help with, a bit broader.

Not sure what to pick? Open a new issue with the `question` label. Asking is normal.

### Commit convention

Use a short form with a prefix marking the kind of change:

```
<type>: <short description, lowercase, no trailing period>
```

Common types:

- `feat:` a new feature
- `fix:` a bug fix
- `docs:` documentation changes (README, this file, etc.)
- `test:` adding or fixing tests
- `refactor:` cleanup with no behavior change
- `chore:` housekeeping (config, tidying)

Example: `fix: handle filenames with spaces`. English or Vietnamese is fine, as long as the next person can read it.

### A note specific to Vietnamese text in this repo

All Vietnamese text in this repo (commits, issues, docs, comments) must never use the em-dash (the U+2014 character). Replace it with a comma, a colon, or a separate sentence. This is a project voice convention; English text is not bound by it.
